## New features
- **Current branding:** the brand logo is in the header of every page. The brand banner is the home page heading and the image shown when the site is shared on social media. The globe from the logo is the browser-tab, home-screen and app icon (`favicon.ico`, `icon-192/512.png`, `apple-touch-icon.png`, `site.webmanifest`).
- **Colour scheme taken from the brand assets:** navy `#03204A` and grey from the logo lettering, gold `#C0904F` from the globe for buttons and accent rules, and sky blue from the banner for light backgrounds. Every text and background pairing meets WCAG AA contrast.
- A responsive layout for phones, tablets and desktops (checked at 320, 360, 390, 414, 768, 1024, 1280, 1920 and 2560 px wide: no horizontal scrolling on any page).
- Complete Spanish version under `/es/` with a working language switcher on every page, linked page-to-page.
- A shop-tour gallery with a keyboard-accessible lightbox (arrow keys, Escape, focus returned to the thumbnail, image counter, captions). Without JavaScript, the thumbnails simply open the full-size images.
- A certificates page with zoomable documents, links to the original files, a details table and full-text transcriptions.
- Mobile menu, tap-to-call phone links and tap-to-email links throughout.
- A contact form that opens the visitor's own email app with the message addressed to info@confidenceaviation.com. There is no server, so no data is stored anywhere.
- A map link for the street address, alongside the original MapQuest links.
- A custom bilingual 404 page listing every page.
- Print styles.

## SEO
- A unique `<title>` and meta description per page. The home title and the About and Capabilities descriptions are the original wording.
- One `<h1>` per page and a logical H2/H3 structure.
- Canonical URLs pointing to `https://www.confidenceaviation.com/…`.
- `hreflang` en / es / x-default on every page and in the sitemap.
- `lang="en"` / `lang="es"`, with `lang="en"` on English terms quoted inside Spanish pages.
- `sitemap.xml` with language alternates; `robots.txt` references it.
- Open Graph metadata, with `og:locale` and its alternate.
- Structured data:
  - `LocalBusiness` on the home page: name, address, phone, fax, email, founding year 1998 and logo, all taken from the original site.
  - `BreadcrumbList` on subpages.
- Descriptive alt text for every content image (the original had none on its photos).
- Text that was previously locked inside images (certificate contents) is now indexable.
- Internal links between related pages, e.g. from Capabilities to the Operations Specifications, and from equipment captions to the gallery.
- Semantic HTML (header, nav, main, footer, aside, article, figure/figcaption, address, dl, table with headers).
- The old URLs are unchanged, so the site keeps its existing search ranking; there are no location pages, invented service pages or keyword stuffing.

## Performance
- Lighthouse (mobile) scored 100 for Performance, 100 for Accessibility, 100 for Best Practices and 100 for SEO on the English and Spanish home pages (with the brand banner), Shop Tour, Certificates and Spanish contact pages. LCP was 1.0–2.0 s, CLS 0 and total blocking time 0 ms, with 65–183 KB transferred per page.
- The home banner is served at 800, 1200 or 2000 px wide depending on the screen, as WebP or JPEG (15–47 KB in WebP); the logo is served at 1× and 2× for sharp display on high-resolution screens.
- Images:
  - WebP with JPEG/PNG fallbacks and `srcset`/`sizes`.
  - Thumbnail sizes for the gallery.
  - `width`/`height` set on every image, so the layout doesn't jump while loading.
  - Lazy-loading below the fold; the first gallery row is loaded eagerly with high priority.
- System fonts only, so no font downloads.
- One CSS file (~20 KB) and one deferred JS file (~5 KB); no frameworks, trackers or third-party scripts. The original's third-party widget script was removed.
- Caching and compression in `.htaccess`:
  - CSS/JS are served with content hashes and cached for a year.
  - Images are cached for 30 days.
  - HTML is always revalidated.
  - Compression uses `mod_deflate`.

## Accessibility
- axe-core scan (WCAG 2.0/2.1 A and AA plus best practices) of all 13 pages at desktop and mobile widths: **0 violations**.
- A skip link ("Skip to main content") is the first tab stop.
- Visible focus outlines on everything you can tab to.
- Keyboard-operable menu (with `aria-expanded`, and Escape closes it).
- The lightbox uses the native `<dialog>`: focus is managed, Escape closes it, the arrow keys navigate and changes are announced to screen readers.
- Colour contrast meets AA; the orange accent was darkened to a 5.2:1 ratio.
- Form fields have labels, required markers, hint text, autocomplete attributes and a status message announced to screen readers.
- Links that open a new tab say so to screen readers, and "HERE" links carry hidden context.
- Landmarks and breadcrumbs on every page, with `aria-current` for the current page.
- `prefers-reduced-motion` turns off all transitions.
- 44 px minimum touch targets for buttons.

## Assumptions
- The crawl on 2026-09-29 is the complete public website. Every page, image and document reachable by links (including JavaScript rollover image names) was fetched. No PDFs or other downloadable documents exist on the site.
- Hidden or commented-out elements (the Language Option block and the Feedzilla widget) are recorded but were not visible content. The Language Option became the working language switcher.
- The decorative header/background tiles carry no information beyond the logo. They are kept at their URLs but not displayed.
- The host is the existing Apache/nginx Plesk server (the old site's `X-Powered-By: PleskLin`), which honours `.htaccess`. The https/www redirect rules are included but **commented out** until someone confirms the hosting panel doesn't already do this, to avoid a redirect loop.
- The contact form uses the visitor's email app (`mailto:`) because the site is static and there is no mail server or form service to send to. Nothing is invented: it sends to the published address.
- Internal links are relative, so the same files work on the real domain and on the GitHub Pages preview.
- Photo alt text describes only what is visible in each photo and makes no claims beyond it.
